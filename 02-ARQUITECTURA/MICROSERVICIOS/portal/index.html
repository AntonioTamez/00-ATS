Microservicios
para novatos

Partes del negocio que viven en procesos separados, con sus propios datos y su propio despliegue. Lo difícil no es el código: es que la red falla.

1. La idea

Gatewaysolo enruta
→ HTTP →
Orders.Servicedatos: pedidos
→ HTTP →
Catalog.Servicedatos: stock

Despliegue independiente

Cada servicio es su propio programa. Cambias Catalog sin tocar Orders.

Datos privados

Nadie lee la base de otro. Si necesitas algo, se lo pides por su API.

Fallos parciales

Catalog puede caer mientras Orders sigue vivo. Hay que diseñar para eso.

Sin transacciones entre servicios

Para deshacer algo se llama otra vez al otro servicio: compensación.

3. Las reglas de independencia

ReglaPor quéCómo se comprueba en el ejemplo
Un servicio no referencia a otroSi se referencian, se despliegan juntos: ya no son independientesTest de arquitectura y análisis del binario con REA
Sin librería compartida de negocioCompartir tipos acopla versiones y desplieguesCada servicio solo referencia ensamblados del framework
Cada uno tiene su copia del contrato del vecinoSe comparte el protocolo (HTTP+JSON), no el códigoCatalogClient define sus DTOs
Datos privadosUna base compartida es un monolito disfrazadoLos *Store no son visibles fuera de su ensamblado
El gateway no tiene negocio"Tuberías tontas, extremos inteligentes"Solo expone su clase de entrada

Las cinco defensas al llamar a otro servicio

1. Timeout            → client.Timeout = 2 s
2. Reintento limitado → solo fallos de red / timeout / 5xx (nunca 4xx)
3. Idempotencia       → POST /reservations lleva reservationId: repetir no repite el efecto
4. Compensación       → DELETE /reservations/{id} (también idempotente)
5. Fallar con claridad→ 503 + Retry-After (Orders) · 502 / 504 (Gateway)

Se combina: cada servicio puede ser un Vertical Slice, Clean/Hexagonal o CQRS por dentro, y entre servicios puedes usar HTTP o eventos. Un sistema real mezcla estilos.

6. Errores típicos

Monolito distribuido

Servicios que se llaman en cadena y se despliegan siempre juntos: todos los costes, ninguna ventaja.

Base de datos compartida

Acopla los servicios por las tablas.

Sin timeouts

Un servicio lento congela a todos los que lo llaman.

Reintentar sin idempotencia

Dobles cobros y doble stock (pruébalo en el simulador).

Cadenas síncronas largas

La disponibilidad se multiplica: 4 servicios al 99 % dan ≈ 96 %.

Empezar con microservicios

Las fronteras equivocadas cuestan caro y operar la flota frena al equipo.
