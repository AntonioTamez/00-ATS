Arquitectura en capas
para novatos

La estructura "de siempre": presentación, negocio y datos. Cada capa usa solo la de abajo. Es simple y suficiente en muchos casos, y es el punto de partida para entender por qué existen Clean, Hexagonal y las demás.

1. La idea

Presentación

Recibe HTTP, devuelve JSON, traduce errores a códigos. No tiene reglas.
▼ usa

Negocio

Las reglas: máximo 3 libros, 14 días de plazo, multa por retraso.
▼ usa

Datos

Tablas y consultas. Guarda y recupera; no decide nada.

Capa ≠ nivel

Una capa es una división del código. Un nivel (tier) es una máquina o proceso distinto. El ejemplo tiene 3 capas en 1 solo nivel.

Capas cerradas

Cada capa solo llama a la inmediata inferior. Presentación nunca toca Datos. Es lo que verifican los tests.

4. ¿Qué toca un cambio?

En capas, una funcionalidad suele atravesar las tres. Compara con agrupar por funcionalidad (Vertical Slice).

En capas

Agrupado por funcionalidad (Vertical Slice)

Dato real del ejemplo: añadir un campo Isbn de punta a punta tocó 3 archivos (uno por capa) y 17 líneas, sin romper ningún test. Es barato aquí; el coste crece con el tamaño del sistema.

5. La flecha de dependencia

Esto es lo que cambia entre capas clásicas y Clean / Hexagonal / Onion:

// Capas clásicas: el negocio recibe una CLASE concreta de datos
public sealed class LoanService(BookRepository books, MemberRepository members, LoanRepository loans, TimeProvider clock)

// Clean/Hexagonal: recibe una INTERFAZ que el negocio define y otro implementa
public sealed class LoanService(IBookRepository books, ...)

7. Errores típicos

Negocio que solo reenvía

Si la capa del medio es un CRUD de paso, añade código sin valor.

Reglas en los endpoints

Se duplican y no se prueban sin HTTP.

Devolver las filas a la UI

La pantalla queda atada a las tablas. Usa DTOs.

Saltarse capas

"La UI consulta la base, es más rápido": las reglas se esquivan.

Un Common para todos

Dependencia oculta y cajón de sastre.

Negocio que solo se prueba con la base real

Tests lentos y frágiles. Necesitas un seam o una base en memoria.
