Screaming Architecture
para novatos

Abre la carpeta de un proyecto. ¿Qué grita? "Soy una aplicación web con controladores" o "soy el sistema de una clínica". El framework es una herramienta; el árbol de carpetas debería hablar del negocio.

1. La idea

Uncle Bob

"Your architectures should tell readers about the system, not about the frameworks you used in your system."

No es una arquitectura nueva

Es una pregunta que se le hace a cualquiera: ¿qué comunica tu estructura? Se aplica encima de capas, Clean, Vertical Slice o Modular Monolith.

La consecuencia práctica

"You shouldn’t need the web server running in order to run your tests." Los casos de uso se prueban sin servidor.

2. La prueba de los 5 segundos

Mira cada árbol de carpetas y adivina de qué trata el sistema.

3. Juego: ¿carpeta técnica o de negocio?

Esta es la misma idea que comprueban los tests (con una lista de palabras: sirve para el error común, no entiende el negocio).

4. ¿Qué carpetas toca un cambio?

Por rol técnico

Por capacidad

5. Las capacidades se conocen en una sola dirección

Haz clic en una celda: ¿puede la capacidad de la fila usar a la de la columna?

Elige una celda.

// ...y Billing lo implementa. Appointments no sabe que Billing existe.

6. Y las demás arquitecturas

Responde a…Relación con Screaming
Layered / Clean / Hexagonal¿Hacia dónde apuntan las dependencias?No dicen cómo se llaman las carpetas: pueden gritar el negocio o no
Vertical Slice¿Cómo agrupo por funcionalidad?El mecanismo más natural para gritar el negocio
Modular Monolith¿Cómo impongo fronteras?Screaming con fronteras que defiende el compilador
DDD¿Cómo nombro el negocio?El lenguaje ubicuo da los nombres de las carpetas

Autocrítica: varios ejemplos de este catálogo (Clean, Hexagonal, Onion, DDD, CQRS, Layered) gritan su arquitectura en los nombres de sus proyectos, porque su objetivo es enseñar esa arquitectura. En un proyecto real, las capas irían dentro de cada capacidad.

7. Errores típicos

Common / Utils gigante

El cajón de sastre que nadie sabe de quién es.

Capas otra vez dentro

Patients/Controllers, Patients/Services: el mismo problema, un nivel más abajo.

Nombres vagos

AppointmentManager no dice nada. CancelAppointment sí.

Solo renombrar carpetas

Si las clases siguen atadas al framework, solo cambió la fachada.

Ciclos entre capacidades

A usa B y B usa A: no se entienden por separado.

Fiarse de una lista de palabras

Detecta lo evidente. El criterio final es: ¿lo reconocería alguien del negocio?
