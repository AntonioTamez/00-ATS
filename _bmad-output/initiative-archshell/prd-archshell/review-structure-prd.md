# ArchShell PRD - Editorial Structure Review

**Purpose read:** this document exists to help the product owner, architect, and implementers of ArchShell v1 agree on what the launch must do and why, and to trace every testable behavior to a stable FR ID.

**Structure model:** Strategic/Context (Pyramid), with a Reference/Database layer for section 4 (FRs are looked up by ID from journeys, other FRs, acceptance criteria, and metrics). The top of the document follows the pyramid well: vision, principles, users, journeys. The problems come from section 4. Incremental patches turned it into a reference layer that has no index, and 4.5 no longer follows the sequence its own description states.

**Word metrics (word_metrics.py):** 7,756 words total. Section 4.5 Feature Workflow = 2,951 words (38% of the document, 22 FRs). Next largest: 4.1 = 551, 4.2 = 468, 4.4 = 452, 4.3 = 529.

Content is not challenged. Every row below is about where something lives, how often it is said, or how readers find it.

## Summary

- **Total recommendations:** 27 (5 MOVE-reorder/regroup, 9 MOVE/MERGE, 6 CONDENSE/CUT, 4 QUESTION, 3 PRESERVE). Some rows carry two tags.
- **Estimated reduction if all accepted:** about 340 words cut or moved out (~4.4% of 7,756). About 340 words added (FR index ~250, glossary terms ~40, step pointers and group labels ~50). Net is roughly neutral; the payoff is findability and one source of truth, not length.
- **Length target:** none provided.
- **Comprehension trade-offs:** none of the cuts remove reader aids. The FR index and the 4.5 grouping add scaffolding. Back-pointers that replace repeated rules (protected set, misfit, attempts) make random-access reading slightly slower, in exchange for removing drift between copies. Drift has already happened in three places (CODEOWNERS scope, verify checks, corpus examples).
- **Root cause:** each FR-43–FR-60 patch added its rule where it was written and restated related rules locally, instead of extending the owning FR. Assigning a single owner per cross-cutting rule (protected set → FR-14, confirmation → FR-59, attempts → FR-26, misfit → FR-28, verify checks → FR-41, corpus → §8) prevents a recurrence.
