- (decision) AD: engine is a stateless state machine; all workflow state (phase, attempts, extensions, pending questions) lives in project files; each engine command reads state from disk and returns the next action; host adapters only execute returned actions and never hold or derive workflow state. Prevents each host reimplementing flow differently; enables resume (FR-24) and model-free verify. Rejected: long-lived daemon (state loss on interruption), host-orchestrated phases (logic duplicated per host)
- (decision) AD: two-tier C# analysis in the .NET pack: per-edit checks use a syntactic parser from Python (tree-sitter C# grammar) within NFR-1; full gates and archshell verify use a Roslyn-based .NET tool (archshell-dotnet-analyzer) invoked as subprocess with JSON in/out. Roslyn verdict is authoritative; the syntactic tier may over-block but never approve what Roslyn rejects, and when unsure it defers to full gates. Rejected: Roslyn-only (cold start breaks NFR-1), build analyzers only (no per-edit feedback)
- (decision) AD: single generation engine: Jinja2 (StrictUndefined) generates everything ArchShell produces, including initial solution (.slnx) and .csproj files, modules added by growth, building blocks, contracts, composition, policies, architecture tests; all output goes through one core normalizer (LF, UTF-8 no BOM, final newline, explicit ordering); generated .gitattributes eol=lf; no formatter ever runs on generated files; .NET SDK used only to execute toolchain (restore, build, test, ef migrations add), never to generate. Rejected: dotnet new for initial scaffold (growth adds modules later -> two definitions of a module diverge; two template formats x21)

- (decision) AD: engine-host protocol archshell/action/v1, closed action set: llm_task (core prompt + JSON schema, result validated by engine NFR-7), ask (closed choices), confirm (summary, accept/decline), instruct_agent (bounded task + allowed files), run (toolchain command, returns exit code + output), report (gap/exhaustion/misfit, terminal), done. Loop: host calls archshell-engine next --feature <slug>, executes action, calls archshell-engine submit <result>, until done/report. Phase 2 CLI runs same loop with LlmProvider executing llm_task; engine unchanged. Host never reinterprets an action; all user-facing text comes from engine (handles FR-39 language); unsupported action -> typed error, no improvisation

- (decision) AD: functional core / imperative shell inside the hexagon: engine domain (scoring, D3, state machine, plan derivation, rendering) is pure: no IO, no clock, no random, no env. - (decision) AD: inputs vs derived artifacts: canonical inputs are base charter, confirmation records, feature plans, vocabulary terms; every generated artifact (architecture.yaml body, arch tests, csproj refs, slnx, composition, policies, contract code, scaffold) is a pure function of the union of inputs.
