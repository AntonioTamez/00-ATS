# Clase 5.2: Permisos de Ejecución

## 🎯 Objetivo
Entender el permiso de ejecución (+x) y por qué lo necesitas.

## ⏱️ Duración: 5 minutos

---

## El Problema

Cuando creas un script nuevo:

```bash
# Crear script
echo '#!/bin/bash
echo "Hola"' > hola.sh

# Intentar ejecutar
./hola.sh
```

Resultado:
```
bash: ./hola.sh: Permission denied
```

¿Por qué? Porque el archivo no tiene **permiso de ejecución**.

---

## Ver los Permisos

```bash
ls -l hola.sh
```

Resultado:
```
-rw-r--r-- 1 usuario grupo 25 Jan 1 10:00 hola.sh
```

Los permisos son: `rw-r--r--`
- `r` = read (lectura) ✅
- `w` = write (escritura) ✅
- `-` = execute (ejecución) ❌ ← ¡Falta!

---

## Agregar Permiso de Ejecución

```bash
# Agregar permiso de ejecución
chmod +x hola.sh

# Verificar
ls -l hola.sh
```

Resultado:
```
-rwxr-xr-x 1 usuario grupo 25 Jan 1 10:00 hola.sh
```

Ahora tiene `x` (ejecución).

---

## Ahora Sí Funciona

```bash
./hola.sh
```

Resultado:
```
Hola
```

---

## ¿Por qué `./`?

El `./` significa "en este directorio". Sin él, el sistema busca el comando en el PATH (como `ls`, `grep`, etc.).

```bash
# ❌ No funciona (no está en el PATH)
hola.sh

# ✅ Funciona (le dices dónde está)
./hola.sh

# ✅ También funciona (ruta completa)
/home/usuario/hola.sh
```

---

## Quitar Permiso de Ejecución

```bash
chmod -x hola.sh
```

---

## 📋 Resumen

```bash
ls -l archivo.sh         # Ver permisos
chmod +x archivo.sh      # Agregar ejecución
chmod -x archivo.sh      # Quitar ejecución
./archivo.sh             # Ejecutar
```

---

## 💡 Tip

Siempre que descargues un script o lo crees nuevo, recuerda:

```bash
chmod +x script.sh
```

---

## 📚 Practica

1. Crea un script `test.sh` con un echo
2. Intenta ejecutarlo con `./test.sh` (verás el error)
3. Agrega permisos con `chmod +x`
4. Ejecútalo de nuevo
