# Clase 6.2: Mejores Prácticas y Debugging de Cron

## 🎯 Objetivo
Aprender a debuggear cron y evitar errores comunes.

## ⏱️ Duración: 15-20 minutos

---

## 📝 Guión de la Clase

### Intro (2 min)
"El 90% de los problemas con cron son: rutas relativas, variables de entorno, o permisos. Hoy aprenderás a evitarlos."

### Demo 1: El problema del PATH (4 min)

```bash
# Cron NO carga tu .bashrc
# Por lo tanto, $PATH es mínimo

# PROBLEMA:
# * * * * * docker ps    # Falla - no encuentra docker

# SOLUCIÓN 1: Rutas absolutas
# * * * * * /usr/bin/docker ps

# SOLUCIÓN 2: Definir PATH en crontab
crontab -e
```

```cron
# Definir PATH al inicio del crontab
PATH=/usr/local/bin:/usr/bin:/bin

# Ahora funcionan los comandos
* * * * * docker ps > ./docker.log 2>&1
```

### Demo 2: Redirigir salida (4 min)

```bash
# Por defecto, cron intenta enviar salida por email
# Si no hay email configurado, se pierde

# SIEMPRE redirigir salida:

# Guardar stdout y stderr a archivo
* * * * * /script.sh >> /var/log/mi-script.log 2>&1

# Descartar salida (si no te importa)
* * * * * /script.sh > /dev/null 2>&1

# Guardar solo errores
* * * * * /script.sh > /dev/null 2>> /var/log/errores.log
```

### Demo 3: Ver logs de cron (3 min)

```bash
# Ver ejecuciones de cron
grep CRON /var/log/syslog

# En tiempo real
tail -f /var/log/syslog | grep CRON

# Con journalctl
journalctl -u cron -f

# Ver errores recientes
journalctl -u cron --since "1 hour ago" | grep -i error
```

### Demo 4: Debugging de scripts (4 min)

```bash
# ANTES de poner en cron, probar manualmente:

# 1. Verificar que el script funciona
/home/usuario/scripts/backup.sh

# 2. Verificar permisos
ls -l /home/usuario/scripts/backup.sh
# Debe ser ejecutable (chmod +x)

# 3. Probar con el mismo entorno de cron
env -i /bin/bash -c '/home/usuario/scripts/backup.sh'

# 4. Script de debug
cat << 'EOF' > ./debug-cron.sh
#!/bin/bash
echo "=== CRON DEBUG ==="
echo "Fecha: $(date)"
echo "Usuario: $(whoami)"
echo "PATH: $PATH"
echo "PWD: $(pwd)"
echo "=================="
env
EOF
chmod +x ./debug-cron.sh

# Agregar a cron temporalmente
# * * * * * ./debug-cron.sh >> ./cron-debug.log 2>&1
```

### Demo 5: Ejemplo completo (3 min)

```cron
# Crontab bien configurado
SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin:/home/usuario/bin
MAILTO=""

# Backup diario con logging
0 3 * * * /home/usuario/scripts/backup.sh >> /var/log/backup.log 2>&1

# Health check cada 5 minutos
*/5 * * * * /usr/bin/curl -s http://localhost/health > /dev/null || echo "$(date): Health check failed" >> /var/log/health.log

# Limpieza semanal
0 4 * * 0 /usr/bin/find /tmp -type f -mtime +7 -delete
```

### Cierre (2 min)
"Rutas absolutas, redirigir salida, verificar logs. Con estas prácticas, tus cron jobs funcionarán siempre."

## 💻 Checklist de Cron

```bash
✅ Script tiene permisos de ejecución (chmod +x)
✅ Usa rutas absolutas en comandos
✅ Define PATH en crontab si es necesario
✅ Redirige stdout y stderr
✅ Probaste el script manualmente primero
✅ Verificaste logs después de la primera ejecución
```
