# Clase 8.1: Diagnóstico de Conectividad

## 🎯 Objetivo
Aprender a diagnosticar problemas de red con curl, telnet, nc y ping.

## ⏱️ Duración: 15-20 minutos

---

## 📝 Guión de la Clase

### Intro (2 min)
"El servidor no responde. ¿Es la red? ¿El servicio? ¿El firewall? Estas herramientas te dan la respuesta en segundos."

### Demo 1: ping - Verificar alcance básico (3 min)

```bash
# Verificar conectividad básica
ping google.com

# Solo 4 paquetes
ping -c 4 192.168.1.1

# Interpretar resultados:
# - Responde = Red OK
# - Request timeout = No alcanzable o ICMP bloqueado
# - TTL = Número de saltos máximos
```

### Demo 2: curl - Pruebas HTTP (5 min)

```bash
# Request simple
curl https://api.github.com

# Solo headers
curl -I https://api.github.com

# Verbose (ver handshake SSL, headers, etc.)
curl -v https://api.github.com

# POST con datos
curl -X POST -d '{"key":"value"}' \
  -H "Content-Type: application/json" \
  https://api.example.com

# Descargar archivo
curl -o archivo.zip https://getsamplefiles.com/download/zip/sample-1.zip
curl -O https://getsamplefiles.com/download/zip/sample-1.zip  # Mismo nombre

# Seguir redirecciones
curl -L http://api.github.com

# Timeout
curl --connect-timeout 5 http://10.255.255.1

# Medir tiempo de comandos
time curl --connect-timeout 3 http://10.255.255.1
```

### Demo 3: telnet y nc - Verificar puertos (4 min)

```bash
# telnet - Verificar puerto abierto
telnet 54.193.59.93 80
telnet google.com 443
# Conecta = Puerto abierto
# Connection refused = Puerto cerrado
# Timeout = Firewall bloquea

# nc (netcat) - Más versátil
nc -zv 54.193.59.93 80      # -z: solo verificar, -v: verbose
nc -zv 54.193.59.93 22

# Escanear rango de puertos
nc -zv 54.193.59.93 80-90
```

### Demo 4: ss/netstat - Ver puertos locales (3 min)

```bash
# Ver puertos en escucha
ss -tulpn
# t = TCP, u = UDP, l = listening, p = proceso, n = numérico

# netstat (más antiguo pero común)
netstat -tulpn

# Ver conexiones establecidas
ss -t state established

# Buscar proceso en puerto específico
ss -tulpn | grep :80
```

### Demo 5: traceroute - Ver ruta de paquetes (2 min)

```bash
# Ver ruta hasta destino
traceroute google.com

# Útil para identificar dónde falla la conexión
# * * * = Nodo no responde (puede ser firewall)
```

### Cierre (2 min)
"Cuando algo no funciona: ping → curl → telnet/nc. En ese orden."

---

## 💻 Comandos de la Clase

```bash
ping -c 4 servidor           # Verificar alcance
curl url                     # Request HTTP
curl -I url                  # Solo headers
curl -v url                  # Verbose
telnet servidor puerto       # Verificar puerto
nc -zv servidor puerto       # Verificar puerto (mejor)
ss -tulpn                    # Puertos locales
traceroute destino           # Ruta de paquetes
```

---

## 📋 Flujo de Diagnóstico

```
1. ping servidor
   ├── OK → Red funciona, continuar
   └── FALLA → Verificar IP, firewall, VPN

2. telnet/nc servidor puerto
   ├── Conecta → Puerto abierto
   ├── Refused → Servicio no corre
   └── Timeout → Firewall bloquea

3. curl -v http://servidor:puerto
   ├── 200 → Todo OK
   ├── 5xx → Error del servidor
   └── Timeout → Verificar paso 2
```
